## Implemented boundary

`official_source_feasibility.py` defines nine versioned contracts: six core KRX
services, two optional Financial Services Commission cross-checks and one
optional OPEN DART current corporation-code bridge. Credentials are accepted
only through the environment. A shared KRX key does not imply approval: each of
the six services has its own explicit approval flag, and the frozen 1,179-request
plan cannot be built until all six are present.

The local evidence store writes response bytes and an envelope create-only with
user-only permissions. Envelopes bind sanitized request identity, contract,
capture time, intended market date, response status/metadata, byte count, raw
hash, parser source/version, license class, retention deadline and blob
reference. Credential echoes in any body or header are rejected before the
store is created. Provider values never enter controlled stdout, logs or
exception text. Replay validates contract, request, parser, retention, byte
count and raw hash with no network dependency.

The reconciler rejects provider-error payloads, schema drift, incomplete
pagination, date mismatch, absent/ambiguous codes, market/ISIN/instrument
inconsistency, invalid OHLCV/listed-shares fields and benchmarks selected only
by display name. Current-only DART mappings are explicitly not historical
identity proof. Unexplained raw/adjusted differences enter a corporate-action
quarantine.

Research blockers remain lexically sorted while summary precedence is fixed:
`AUTH_REQUIRED`, `NO_GO_REPRODUCIBILITY`, `NO_GO_SOURCE_SCHEMA`, then
`PARTIAL_IDENTITY_BRIDGE`. Diagnostics can add blockers but cannot clear or
promote a primary result. The KRX hard cap is 1,800 calls; optional official
cross-checks have their own combined 600-call cap.

identity before storage creation. Secret parameter names are case-insensitive;
raw and upper/lower percent-encoded credential values in identities, bodies or
headers are rejected with zero blobs, envelopes or conclusion input.

The complete replay-critical envelope is hashed and the hash names the envelope
file. Replay validates that binding as well as the contract, provider, license,
redistribution, parser and retention fields. Envelope/blob references must be
simple content-addressed basenames. Files are opened without following symlinks
relative to a root descriptor reached component-by-component without following
symlinks. Root identity is rechecked; replacement during capture rolls back its

the original root, lock and ledger. The authority stores the expected ledger

## Fork-lineage Builder correction

The PID-lineage guard now runs before acquiring the inherited registry mutex.
When a fork child inherits a nonempty authority registry, it raises categorical
`PROBE_AUTHORITY_FORKED` immediately. It does not close held descriptors, clear
the registry, reset the PID binding or create a new authority, so parent exit
cannot turn the fork child into a fresh probe execution. This ordering also
avoids deadlock if the mutex was held by another parent thread at fork time.

An independently executed future process initializes the module with its own
PID and an empty registry and may start a new documented process-lifetime
execution. A fork child with an inherited active registry remains in the same
execution lineage regardless of whether its parent is still alive.
