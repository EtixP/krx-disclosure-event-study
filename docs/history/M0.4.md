# M0.4 — Corporate-action / price-adjustment audit

## Objective

Make the stock-price basis explicit, verify current pykrx behavior, and test
the categories most exposed to corporate-action adjustment without selecting a
methodology to improve results.

## State before M0.4

`MarketDataClient.fetch_ohlcv` omitted pykrx's `adjusted` argument. The
installed default happened to be `True`, but neither callers nor stored output
made that choice explicit. M0.2 verification had also found one 2026 KOSDAQ
bonus-issue row whose absolute prices refetched at five times their stored
scale.

## Verified provider behavior

The audited environment uses `pykrx==1.2.8`. Its
[`get_market_ohlcv_by_date` implementation](https://github.com/sharebook-kr/pykrx/blob/v1.2.8/pykrx/stock/stock_api.py)
defaults `adjusted=True`; `True` calls the Naver Finance date-series adapter,
while `False` calls the KRX adapter. A pykrx maintainer gives the same source
distinction and explains why the adjusted path exists in
[issue #65](https://github.com/sharebook-kr/pykrx/issues/65). The
[v1.2.8 release](https://github.com/sharebook-kr/pykrx/releases/tag/v1.2.8)
introduced credential-backed KRX session handling.

Live probes on 2026-09-01 confirmed both branches in this environment:

- `adjusted=True` returned Naver daily history;
- `adjusted=False` attempted the KRX route and failed without `KRX_ID` and
  `KRX_PW`; there is no fallback to adjusted data.

The provider observation is pinned in
`artifacts/m0_4/provider_observations.json`. It is dated evidence, not a claim
that future refetches will preserve an old adjustment vintage.

## Chosen policy

Historical event-study returns use `PriceAdjustment.VENDOR_ADJUSTED`, mapped
explicitly to pykrx `adjusted=True`. This choice was fixed before comparing
M0.4 results.

The research question is post-announcement return, not the raw price gap from a
split, bonus issue, or consolidation. A raw close ratio can turn a mechanical
change in units per share into a false loss or gain. A continuity-preserving
series is therefore the more defensible common return basis across categories.

The boundary is now explicit:

- every production OHLCV call must pass a `PriceAdjustment` enum;
- the wrapper passes `freq="d"`, `adjusted=...`, and `name_display=False`
  explicitly and labels returned frames with the policy and provider route;
- new event-study rows carry `price_adjustment` and `price_source` fields;
- `pykrx` is pinned to 1.2.8 because the source dispatch is part of the policy;
- committed observations, not a later refetch, define a historical artifact's
  reproducible price vintage.

Adjusted historical closes are outcome-analysis inputs. They are not asserted
to be executable quotes or future paper-fill prices.

## Corporate-action audit

The deterministic audit covers both adjustment-sensitive headline categories:

| Category | Rows | Complete | Complete explicit rights-drop rows | Crossed using committed union | Crossed using pinned DART calendar |
|---|---:|---:|---:|---:|---:|
| bonus issue | 840 | 828 | 242 | 4 | 4 |
| rights offering | 5,991 | 5,911 | 192 | 66 | 69 |

The committed union contains 441 unique rights-drop receipts. The pinned raw
DART slice contains 499 receipts from the same local 1,209,249-row disclosure
snapshot. Every committed receipt is present in the raw slice; the 58 raw
records absent from the two title-filtered category files add three crossed
rights-offering windows. The audit therefore records both the reproducible
committed-union census (70 windows) and the more complete raw-source census
(73 windows), rather than treating either population as the other.

Seven captured fresh-provider cases match nine category rows. Five cases,
covering seven previously identified crossings, matched stored closes exactly.
Two `300120` cases reproduced a uniform 5× vintage revision: the explicit
2026-02-26 bonus-issue rights drop and the formerly omitted 2026-02-19
rights-offering window that ends on that drop date.

The prior scale anomaly was LaonPeople (`300120`) on 2026-02-26. Stored closes
were `1,607 / 1,735 / 1,585 / 1,089`; the fresh series returned
`8,035 / 8,675 / 7,925 / 5,445`, exactly 5× at every horizon. The local DART
record contains a later `주식병합결정` filing, receipt `20260519900417`.
Because the scale factor is uniform, all three event returns are identical to
machine precision. The cross-category rights row likewise changed from
`1,567 / 1,528 / 1,532 / 1,607` to
`7,835 / 7,640 / 7,660 / 8,035`, exactly 5× with no return change. Regression
tests preserve both cases and the 4/66 committed-union versus 4/69 raw-DART
census.

## Result comparison

Making the existing basis explicit changes no stored event price, return,
headline mean, fold count, or verdict. In particular:

- bonus issue remains 828 scored events, `+0.093%` abnormal realistic mean,
  6/10 abnormal positive folds, verdict `neutral`;
- rights offering remains 5,911 scored events, `+0.111%` abnormal realistic
  mean, 7/11 abnormal positive folds, verdict `positive_noisy` but below the
  tradability bar.

The deterministic comparison is
`artifacts/m0_4/price_adjustment_audit.json`.

## Alternatives not chosen

- **Unadjusted KRX prices for all research.** Rejected because mechanical unit
  changes would contaminate announcement returns, and the current KRX route is
  unavailable without credentials.
- **Different bases by event category.** Rejected because category comparisons
  would no longer have one return definition.
- **Treat adjusted prices as total shareholder return.** Rejected. The vendor
  adjustment methodology is not sufficiently documented to claim exact rights,
  dividend, or entitlement wealth accounting.

## Remaining limitations and handoff invariants

- Naver's historical adjusted scale can revise after future corporate actions;
  absolute closes are not vintage-stable.
- `dart_right_drop_calendar.json` is a pinned snapshot of a local DART extract;
  future database vintages must be captured explicitly rather than silently
  changing the verified artifact.
- The study has not reconstructed historical KRX raw closes or corporate-action
  entitlement cash flows and therefore does not report formal total shareholder
  return.
- Future execution work must use contemporaneous executable-price semantics,
  not silently reuse adjusted historical closes as fills.
- Do not remove the mandatory adjustment argument, silently change the pykrx
  route/version, or mutate verified M0.1–M0.3 artifacts.

## Independent verification result

M0.4 was returned to `IN PROGRESS` on 2026-09-01. The Verifier independently
confirmed the installed pykrx source dispatch, explicit production calls,
dependency pin, all six captured adjusted-provider cases, the no-fallback KRX
probe, deterministic artifact, unchanged M0.1–M0.3 hashes, and unchanged
corporate-category research conclusions. Focused tests passed 12/12 and the
full suite passed 192/192.

The corporate-action window census was incomplete. `_right_drop_crossings`
constructs its rights-drop dates from only the category frame currently being
audited. It cannot detect a rights-offering row whose return window crosses a
bonus-issue rights drop. Combining both committed corporate-action files finds
4 affected bonus-issue rows and 66 affected rights-offering rows, not 4 and 3.
The local raw DART table finds 73 total crossed windows rather than the claimed
7, including three whose drop events are absent from the committed category
snapshots.

One omitted row is stock `300120`'s 2026-02-19 rights-offering event, whose T+5
date is the 2026-02-26 bonus-issue rights drop. A fresh adjusted retrieval
changed all four stored closes by exactly 5×, independently reproducing the
same vintage revision highlighted elsewhere in this audit. Its returns remain
unchanged, but it demonstrates that the omission is directly relevant. The
audit input/calendar, artifact, regression expectations, and seven-window
documentation must be corrected before M0.4 can be verified. M0.5 remains
unstarted.

## Builder correction after independent failure

The correction replaces the category-local calendar with two explicit shared
calendars. The primary completeness audit uses the pinned 499-event DART slice;
the 441-event union of committed bonus/right category files remains as a
reproducible diagnostic. The generated artifact now reports 4 bonus + 66 rights
crossings for the committed union and 4 + 69 for raw DART, including source
receipt numbers and exact window dates.

The pinned slice regenerated exactly from the local SQLite snapshot. The
formerly omitted `300120` rights row is now a provider observation and a
regression assertion; its exact 5× revision leaves all returns unchanged. The
M0.4 artifact schema advances to version 2. Research logic and M0.3 category
headlines do not change, and the verified M0.1–M0.3 artifacts remain immutable.
