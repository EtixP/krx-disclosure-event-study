# M0.3 — Benchmark-adjusted event returns

## Objective

Separate disclosure-associated stock movement from broad KOSPI/KOSDAQ movement
without selecting a benchmark after seeing results, changing event definitions,
or introducing future outcomes into decision-time features.

## State before

The research reported stock simple returns net of dated transaction costs. A
KOSPI or KOSDAQ rally during an event window was therefore credited to the
disclosure. The M0.2 raw-return result is retained as the comparison baseline.

## Benchmark assignment and source

The assignment is fixed by listing market:

| Stock market | Benchmark | Naver symbol | pykrx/KRX ticker reference |
|---|---|---|---|
| KOSPI | broad KOSPI price index | `KOSPI` | `1001` |
| KOSDAQ | broad KOSDAQ price index | `KOSDAQ` | `2001` |

KRX defines KOSPI as the composite index for its main board and describes it as
market-capitalization based. KRX likewise describes the KOSDAQ series as
indices calculated from KOSDAQ-listed stocks:

- [KRX KOSPI market and index description](https://global.krx.co.kr/contents/GLB/02/0201/0201010100/GLB0201010100.jsp)
- [KRX KOSDAQ series description](https://index.krx.co.kr/contents/MKD/03/0304/03040300/MKD03040300.jsp)
- [KRX Open API index-service list](https://openapi.krx.co.kr/contents/OPP/INFO/service/OPPINFO004.cmd)

KRX's registered Open API was not configured in this repository. The
unauthenticated KRX index-history path used by the installed `pykrx` returned
empty/error responses during implementation, including with
`name_display=False`. M0.3 therefore uses Naver Finance's public domestic-index
daily history endpoint as the delivery source:

```text
https://m.stock.naver.com/api/index/{KOSPI|KOSDAQ}/price
```

This provider choice is a limitation, not a hidden fallback. The normalized
cache is `data/benchmark_indices.csv`; its endpoint, retrieval timestamp, date
range, and alignment policy are in `data/benchmark_indices.meta.json`.

## Alignment and return methodology

The normalized cache contains 1,226 observations per market from 2021-06-28
through 2026-07-01. Each event already records its actual stock observation
dates (`t0_date`, `t+1_date`, `t+2_date`, `t+5_date`). M0.3 looks up the assigned
index close on those exact dates.

It does not:

- use the Nth next index row;
- substitute the nearest market date;
- forward-fill or backward-fill;
- convert an unavailable index observation to zero.

For entry date `a` and exit date `b`:

```text
stock_return     = stock_close[b] / stock_close[a] - 1
benchmark_return = index_close[b] / index_close[a] - 1
abnormal_return  = stock_return - benchmark_return
abnormal_net     = abnormal_return - dated_roundtrip_cost
```

The backfill ran in strict mode across nine event-study CSVs: 34,686 rows. Every
benchmark lookup requested by an available stock observation date succeeded.
Rows without a stock observation remain missing at both stock and benchmark
layers. Headline consumers reject incomplete benchmark context.

## Architecture and chronology

`src/kdtb/data/benchmarks.py` is the shared boundary for source retrieval,
normalization, exact-date alignment, and missing-data validation. It returns
raw benchmark closes, benchmark returns, and abnormal returns, so later
historical-context APIs can expose attribution without rebuilding domain logic.

Benchmark outcomes are used only as realized research/reward labels. The
decision-time feature list is unchanged and contains no benchmark exit close or
future return. Learner training/validation/test chronology is unchanged. Frozen
M0.1 and M0.2 artifacts invoke explicit raw-return modes; current research uses
abnormal rewards.

## Result changes

No parameter or benchmark was searched to preserve a positive result.

- Buyback realistic mean: `+0.143%` raw → `−0.028%` abnormal; category verdict
  `positive_noisy` → `neutral`.
- Buyback learner selection lift: `+0.022%` raw → `−0.037%` abnormal; verdict
  `positive_selective_edge` → `no_selection_edge`.
- Buyback time-aware mean: `+0.458%` raw → `+0.164%` abnormal. The timing delta
  is `+0.257%` and positive in 9/10 folds rather than the raw 10/10.
- Shareholder-change realistic mean: `−1.103%` raw → `−1.396%` abnormal; the
  negative blacklist finding strengthens.
- Rights offering becomes `positive_noisy`, but its abnormal realistic mean is
  only `+0.111%`; no category is `positive_robust` or clears the tradability
  gates.
- The 24-month v2 paper simulation remains `+0.151%` raw cash PnL but is
  `−1.174%` abnormal. Raw simulated cash PnL remains the execution quantity;
  abnormal return is attribution, not spendable PnL.

The deterministic comparison and provenance hashes are in
`artifacts/m0_3/benchmark_adjustment_comparison.json`.

## Remaining limitations

- These are price indices, not total-return indices.
- The adjustment assumes stock beta equals one.
- No sector, size, style, or estimated-beta matching is attempted.
- The Naver endpoint is public but undocumented and may drift; the checked-in
  normalized cache protects reproduction, while refreshes must be reverified.
- Corporate-action price adjustment remains unresolved and belongs to M0.4.

## Handoff invariants

- Keep the KOSPI/KOSDAQ assignment fixed unless a future milestone changes the
  methodology prospectively.
- Align on the stock row's exact entry/exit dates.
- Never turn missing benchmark data into zero or a filled value.
- Keep raw cash PnL distinct from abnormal-return attribution.
- Keep benchmark outcomes out of decision-time features.

## Independent verification result

M0.3 was returned to `IN PROGRESS` on 2026-08-31. The verifier reproduced the
provider cache, exact-date formulas, comparison artifact, tests, and research
results, but found three release-blocking boundary failures:

- pandas enrichment removed leading zeros from fixed-width source identifiers
  and rewrote existing return serialization;
- non-finite benchmark closes pass normalization and `strict=True` can label
  missing benchmark values as `complete`;
- historical M0.1/M0.2 provenance records were rewritten to current M0.3
  inputs/sources despite their explicit immutability policy.

These corrections belong to M0.3. M0.4 remains unstarted.

## Builder correction after returned verification

The 2026-09-01 correction retains the verification failure above as historical
evidence and fixes each boundary:

- Event enrichment now reads source cells as strings and rewrites only the
  benchmark columns. It restored exactly 32,510 changed `corp_code` and 10,633
  changed `stock_code` cells, plus the original return lexemes. Removing the
  benchmark columns from each of the nine outputs reproduces its pinned
  pre-M0.3 checksum; rerunning enrichment is idempotent.
- Source fetch and normalization reject `NaN`, positive infinity, negative
  infinity, and non-positive closes. Downstream completeness validation also
  rejects non-finite closes. Blank stock observations remain explicitly missing
  rather than being parsed as numeric values.
- The M0.1 manifest is restored to SHA-256 `7618e0d6…` and the M0.2 comparison
  to `b529d30e…`, the exact independently verified bytes. Their commands now
  refuse in-place mutation; current-tree replays require separate output paths.

After repair, all 34,686 rows and 103,624 price-bearing horizons reconciled to
the exact-date formulas. The regenerated M0.3 research payload is identical to
the returned implementation; only M0.3 input/source provenance changed. All
affected analyses reran, focused tests passed 31/31, and the full suite passed
185/185. M0.3 is `AWAITING VERIFICATION`; M0.4 is still unstarted.
