# M1.4 — Historical-context query service

## Objective

Given one canonical M1.1 event and a decision timestamp, return reproducible
historical outcome context without turning it into a signal. Selection,
methodology, data vintage, uncertainty, and replay cutoffs must be inspectable.

## Dataset boundary

M1.4 reads the seven committed `data/event_study_<category>.csv` files. These
are the reproducible Phase 0 research vintage with exact stock observation
dates, fixed KOSPI/KOSDAQ benchmark closes, and price-adjustment provenance.
Canonical event types map directly to their existing category names; no title
classifier or parallel live-only domain logic is introduced.

The historical files deliberately remain one row per research receipt. They do
not contain an authoritative historical canonical-lineage backfill. The query
therefore labels its comparables as receipt-level exploratory observations. It
does not guess relationships from title or date. The current event must have
`self_contained` or `complete` lineage so all of its known receipts can be
excluded safely; partial and unresolved current events fail explicitly.

## Auditable comparable selection

For a supported event, selection is exactly:

1. choose the committed source for its canonical event type;
2. retain the same KOSPI/KOSDAQ listing market;
3. require source receipt number strictly before the current event's latest
   known receipt;
4. exclude the primary, related, and provenance receipts in the current
   canonical lineage;
5. require issuer identity, event/T+1/T+5 dates, and positive T+1/T+5 stock
   closes; and
6. require T+5 strictly before the `assessed_at` date in Seoul.

The strict date rule is conservative: a daily close dated on the assessment
day is excluded even after the nominal close because the stored research input
does not carry an outcome-publication timestamp. This avoids inventing
intraday availability. Shared M1.3 chronology also rejects a query made before
the current event's latest source timestamp.

The result records source rows, same-market rows, earlier-receipt rows,
current-lineage exclusions, missing stock outcomes, unavailable outcomes, and
selected rows. Those counts must reconcile. It also stores every selected
receipt number, immutable per-row derived outcomes, and a SHA-256 over those
outcomes. The Pydantic result rechecks the hash and cutoff invariants.

## Phase 0 metric reuse

For each selected row:

```text
stock gross    = stock T+5 close / stock T+1 close - 1
benchmark gross = index T+5 close / index T+1 close - 1
abnormal net   = stock gross - benchmark gross - dated roundtrip cost
```

The benchmark source/symbol/alignment boundary is the verified M0.3 machinery.
The service fixes the default M0.2 `CostModel`; callers cannot silently inject
a tuned cost model. Mean, median, standard deviation, positive fraction, and
profit factor come from the Phase 0 `compute` primitive. The 95% pointwise
interval comes from M0.5's deterministic issuer-clustered percentile bootstrap
with 10,000 draws and seed zero by default.

At least two events from at least two stock-code issuer clusters are required
for inferred metrics. Smaller samples return `insufficient_history` with the
sample and selected rows still visible. The interval remains exploratory and
does not solve common-date shocks, overlapping holding windows, multiplicity,
or historical data reuse.

## Dataset provenance and versioning

Each result records:

- context and dataset version `m1.4-v1`;
- caller-visible dataset ID;
- exact category source path, byte SHA-256, row count, and maximum stored T+5
  date;
- current receipt cutoff and exclusive outcome-date cutoff;
- exact selected receipt set and selected-row hash; and
- inference configuration and explicit stock/benchmark/cost attribution.

The file is hashed before and after reading; a concurrent vintage change fails.
Reusing a dataset ID with different bytes is visible through `source_sha256`.
M1.4 does not persist or mutate the committed research data.

## Validation

- Focused historical-context/significance/inference/cost/benchmark tests:
  `72 passed`.
- Full repository suite: `300 passed`.
- Fixture attacks cover same-day/future outcomes, current-lineage
  self-comparison, incomplete lineage, missing benchmarks, invalid policy,
  insufficient samples, immutable output, and altered selection hashes.
- All seven committed categories in both KOSPI and KOSDAQ—28,728 complete
  outcomes—reconcile to Phase 0 row counts, means, medians, and positive
  fractions.
- A full-cutoff KOSPI supply-contract smoke query returned 4,356 outcomes from
  275 issuers and exactly matched the independently constructed Phase 0 slice.
- M1.1 and M0.5 regenerated byte-for-byte at `33ff2517…` and `3677a4c2…`;
  M0.1–M0.4 hashes and all category research outputs remained unchanged.

## Handoff invariants

- Do not call receipt-level comparables canonical historical events until an
  authoritative lineage backfill exists.
- Do not relax the strict outcome cutoff without persisting verifiable outcome
  availability timestamps.
- Do not allow missing benchmark data, unknown markets, or custom costs to
  silently change the sample or metric.
- Preserve the no-recommendation output boundary.
- M1.5 may format this result for alerts and replay, but must not duplicate its
  selection or metric logic.

## Independent verification failure (2026-09-08)

The service's direct outputs reproduced all 28,728 outcomes and Phase 0
metrics, but the schema-level provenance claim did not survive adversarial
deserialization:

- an arbitrary `mean_abnormal_net_return` was accepted despite disagreeing
  with the selected outcomes; and
- a selected row whose abnormal return was changed by `+0.5` was accepted
  after recomputing `selected_rows_sha256`, even though its unchanged stock,
  benchmark, and cost components implied the original return.

The hash detects accidental changes only while treated as authoritative; it
does not prove that a caller recomputed derived fields with the verified Phase
0 machinery. The result validator must tie each derived row and every reported
aggregate/inference field back to the recorded inputs and policy, with direct
regressions for rehashed semantic contradictions.

Focused tests still passed `72/72`, the full suite passed `300/300`, and all
28,728 real outcomes reconciled. Black, compilation, and diff checks passed.
M1.1 and M0.5 regenerated byte-for-byte at `33ff2517…` and `3677a4c2…`; all
upstream artifact hashes and research conclusions remained unchanged.

M1.4 returns to `IN PROGRESS`. M1.5 was not started.

## Builder correction after verification failure (2026-09-08)

The immutable schema now enforces semantic as well as structural integrity.
Each `HistoricalComparableOutcome` recomputes
`stock_gross_return - benchmark_gross_return - modeled_cost_fraction` and
requires exact agreement with `abnormal_net_return`. Consequently, changing a
row and recomputing its selection hash still fails when its retained components
contradict the derived return.

For available context, `HistoricalContextResult` independently reruns Phase
0's `compute` over the embedded abnormal returns and M0.5's deterministic
issuer-clustered bootstrap using the recorded confidence level, draw count, and
seed. It checks all three attribution means, abnormal mean/median/standard
deviation, positive fraction, profit factor, and both interval bounds. Counts
and fixed methodology labels remain covered by the existing schema invariants.

Direct tests reproduce the rehashed `+0.5` row attack and the aggregate-mean
attack. Parameterized cases falsify every other derived aggregate and interval
field. Focused tests pass `83/83`; the full suite passes `311/311`. All 28,728
committed category/market outcomes still reconcile under the strengthened
schema. Black, compilation, and diff checks pass. M1.1 and M0.5 regenerate
byte-for-byte at `33ff2517…` and `3677a4c2…`; no research result changes.

## Independent re-verification (2026-09-08)

The original arbitrary-mean and rehashed contradictory-row attacks now fail.
An independently constructed one-ULP row change also fails before its updated
row hash can make it acceptable. One-ULP mutations of each of the ten derived
metric fields fail, as do stale interval bounds after changes to the recorded
confidence level, resample count, or seed. An unchanged result survives a JSON
round-trip, and the `profit_factor=None` edge for an all-positive two-issuer
sample remains valid while a forged numeric value fails.

Independent source-level reconstruction again matched every row equation and
aggregate across all seven categories and both markets, totaling 28,728
outcomes. KOSPI supply contracts remained 4,356 outcomes from 275 issuers.
Focused tests passed `83/83`; the full suite passed `311/311`; Black,
compilation, and diff checks passed. M1.1 and M0.5 regenerated byte-for-byte at
`33ff2517…` and `3677a4c2…`, and all earlier artifact hashes and research
conclusions remained unchanged.

M1.4 is accepted as `VERIFIED`. M1.5 was not started.
