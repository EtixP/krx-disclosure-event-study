## Defect and daily contract

The old loader discarded receipt/issuer/stock identity and reconstructed dates.
Outer folds used event dates; the inner split cut rows, allowing a same-day
cohort to straddle training/calibration. Neither threshold selection nor
promotion purged outcomes that ended after the next period began. For example,
buyback receipt `20231228000427` ends on 2024-01-08 and could influence a
2024H1 model choice. Event dates alone do not establish label availability.

Strict `load_mock_trades` now retains string `id`, `receipt_no`, `corp_code`,
`stock_code`, aliases `event_id`/`issuer_id`, and stable category/receipt `row_id`.
It retains source dates and supplies `feature_observation_date = t0_date`,
`entry_date = decision_date = t+1_date`, and `label_end_date = t+5_date`.
All dates are exact timezone-free days. The feature observation must precede
 the decision day; outcomes ending on a cutoff day are unavailable that day.
Required metadata is checked before early abstention, including tiny samples.
When source-date or identity aliases are supplied, contradictions fail closed.

The admission horizon is the pinned `data/benchmark_indices.csv`, SHA-256
`a70c5f9ae3ae7b8349fe489b720bb01411ba60437b4a85927b87c6a6acc7e062`.
T0 is the first **observed benchmark session** on/after the event; entry and exit
must be its offsets 1 and 5. A changed cache fails the default hash pin. Invalid
calendar dates, duplicate dates, nonpositive closes and differing market date
sets fail explicitly. Missing/malformed/reversed row dates, dates outside the
observed horizon, unsupported markets, mismatched offsets, missing/duplicate
identities and unusable prices quarantine with stable reason counts and records.
There is no invented maximum calendar gap or exchange-holiday reconstruction.

The horizon is not authoritative evidence that every exchange session is
present. Likewise, reconstructed T0 is not proof that the adjusted price or
filing version existed then. These limits are explicit in the dataset audit,
CLI, artifact and research summaries.

## Fit, calibration and promotion

- Outer folds use decision days, with cutoffs fixed at January 1 / July 1.
  Sparse first observations do not move a cutoff later into the period.
- Challenger candidates precede the outer validation period. The inner 70/30
  split uses unique candidate decision dates, before inspecting label maturity.
  Rows from one decision date never cross that boundary.
- Fit labels must end strictly before the first calibration decision day.
  Calibration labels must end strictly before the outer validation period start.
- Promotion uses only prior validation-fold outcomes ending strictly before
  the test period start. The test period never determines earlier model state.
- The classifier, feature vector, dated cost model, threshold grid, seed and
  PnL promotion objective remain unchanged. Minimum usable support is 42 fit
  and 18 calibration rows, derived from existing `min_train=60, val_frac=0.3`.
- Insufficient date groups/purged support or a single fit class abstain with
  diagnostics. With no mature promotion outcomes, no new promotion occurs;
  an already frozen incumbent remains usable. The initial incumbent is
  `NeverTrade`. An abstaining challenger can beat a loss-making incumbent under
  the unchanged promotion objective.
- Every fold records candidate/eligible/purged counts, eligible row identities,
  fixed cutoffs, challenger threshold, actual fitted-state fingerprints,
  incumbent training/selection cutoffs and frozen test decisions. Retained
  incumbents keep their original cutoffs, not the current challenger's cutoffs.

Finite unavailable-label perturbations cannot change an earlier model,
threshold, promotion or decision. Nonfinite/malformed input may invalidate the
whole request; that is a separate fail-closed input contract, not a claim that
arbitrary corruption must be ignored.

## Deterministic ordering correction

Admitted data sorts by decision date and stable row ID. Duplicate identities
are quarantined in full. Two rejected duplicates can share row ID and reason
while differing in their source dates; sorting only on ID/reason retained input
order in that diagnostic tie. The final correction uses canonical JSON of the
entire exclusion record as a third sort key. A direct reversed-input regression
checks identical exclusion lists and counts. The input-byte hash properly
changes when CSV ordering changes; semantic decisions/exclusions do not.

## Historical reproduction and provenance

The public learner is strict, including raw reward mode. It never infers
historical chronology from missing metadata or a return basis.
`kdtb.research.historical_learning` is the explicit compatibility adapter used
only by frozen-artifact builders and the labeled legacy intraday script.
It preserves the old feature/model/cost/objective and fold serialization.
Historical supply enrichment is also refused by that adapter: an original
filing-version provenance chain is unavailable even independently of DB hashes.

Current builders emit actual current generator-source hashes. Their scientific
payloads match historical payloads exactly after the established 10-decimal
canonical JSON serialization; their new source manifests are not represented
as the old execution provenance. The updated artifact tests separately verify
current source hashes and old claims against preserved old source bytes.

Ten affected pre-M0.6 source files are retained byte-for-byte in
`artifacts/m0_6/legacy_sources/`, enumerated by `legacy_source_manifest.json`.
`replay_historical_learner_sources.py` builds a temporary tree from current
`src/` and `scripts/`, overlays those exact archived bytes, copies unchanged
requirements/project metadata, and exposes only CSV/JSON inputs and frozen
artifact directories. Its child process has an explicit temporary-tree
PYTHONPATH. No database is exposed or opened by the replay.

The replay actually executes the old sources. M0.1 learner, M0.3 and M0.5
outputs match frozen bytes. M0.2's canonical scientific payload matches;
full M0.2 bytes differ due to input benchmark enrichment/source drift that
predates M0.6. An initial unrounded in-memory comparison exposed only expected
floating serialization differences (e.g. −0.016600000000000004 versus −0.0166);
comparison now uses the historical canonical serializer, without tolerances
or numeric retuning. Old artifact files were never rewritten.

## Verifier-returned compatibility repair (2026-10-02)

Independent verification caught that the modified M0.3/M0.5 no-argument
commands still wrote to their frozen artifact paths. Because current execution
source hashes had changed, those defaults could corrupt historical provenance
and invalidate M0.5's M0.3 upstream pin. Verification witnessed the target by
intercepting writes; it did not overwrite the frozen files.

M0.2/M0.3/M0.5 defaults now verify the frozen SHA-256 and return without building
or writing. An explicit `--output` is required to generate a current-source
replay. The path must not exist and must resolve outside repository `data/`,
`sources/`, and `artifacts/` trees. Symlink aliases are checked after resolution.
An optional exclusive mode in the canonical writer publishes completed bytes
with an atomic link, refusing even a destination created during generation.
The ordinary serializer remains byte-identical; existing non-CLI uses retain
its original replace behavior unless exclusive mode is requested.

The preserved-source replay runner uses the same path guard and exclusive
writer. The historical intraday default no longer accepts `--db` or opens
SQLite: it loads `artifacts/baselines/pre_revision/inputs/buyback_filing_times.csv`,
pinned at `0c61572d3e128a82b0b7d79c236541d0f5940db7a4fe1d1dd3ae061fa0ee99e5`,
and reads receipt, event, issuer and stock identifiers as strings. It rejects
unsupported categories and supply-contract original-version enrichment with
concise diagnostics. The historical same-day-fill/learner assumptions remain
explicitly labeled; this change supplies no new execution evidence.

Current M0.2/M0.3 manifests now include the actually executed `baseline.py`.
Direct tests check provenance closure and exact canonical scientific payloads.
Guard tests witness no-argument no-build/no-write behavior, corrupt frozen bytes,
existing and protected outputs, symlink routing, successful fresh publication,
and a competing writer creating the destination during generation. Intraday
tests prohibit every SQLite connection, call the actual default entry point,
check the pinned cohort, preserve leading-zero IDs and reject unversioned supply.

The corrected report's scientific results are unchanged; its source hash changed
because the canonical writer module changed. Archived source bytes and all old
artifacts remain unchanged. This repair remains part of M0.6.

no-DB historical entry points. The independent record is

rejects incompatible learner windows. Authoritative exchange-session coverage,
historical listing/security membership, original adjusted-price vintages,
filing availability, event lineage and receipt-level dependence remain open.
Broader category/timing/blacklist estimates stay frozen/exploratory pending a
separately scoped window/security-master/source audit. No later milestone was
started; M3.2 remains NOT STARTED.
